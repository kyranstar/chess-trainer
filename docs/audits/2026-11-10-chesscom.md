# Chess.com source-feasibility audit

Audit date: 2026-11-10. Scope: public pages only, no login, no access-control bypass.

## Method and how to read the verification labels

- Pages were read with a server-side fetch tool (WebFetch) that returns the page through an extraction model. That model refuses long verbatim reproduction, so every quote below is a short fragment (under ~120 characters). Where a sentence was longer it is given as consecutive fragments. Treat legal quotes as accurate-but-fragmentary and re-read the source page in a browser before relying on them.
- Request volume: 37 distinct `www.chess.com` pages (40 fetch calls, a few repeats for quotes), 3 distinct `support.chess.com` pages, 3 serial requests to `api.chess.com`, 1 direct `curl` to `www.chess.com` (blocked, see below).
- Labels, used exactly as requested:
  - `fetched-ok` — I fetched the URL and the returned page title/content matched.
  - `search-result-only` — the URL appeared in a web search result; I did not fetch it (or the fetch failed).
  - `unverified` — I did not fetch this URL. Where I add "(listed on X)", the URL was not guessed: it was extracted from the link list of a `fetched-ok` page X, but the target itself was never opened. Where there is no such note, it is constructed.

### Blocking finding (plain statement)

- Direct scripted access to `www.chess.com` IS blocked. `curl https://www.chess.com/robots.txt` from this machine returned **HTTP 403 with a Cloudflare "Just a moment..." managed challenge** ("Enable JavaScript and cookies to continue"). I did not attempt to get around it (no UA spoofing, no cookies).
- The hosted WebFetch tool was NOT blocked for any public page I requested (lessons catalog, course pages, legal page, news page, support site).
- `api.chess.com` (PubAPI) was NOT blocked for plain `curl` with a generic User-Agent: 3 of 3 requests returned HTTP 200.
- Individual lesson pages return only the site shell to a non-browser fetch: `https://www.chess.com/lessons/capturing-pieces/counting-the-captures` (`fetched-ok`, title "Counting Captures | Chess Lessons - Chess.com") came back with header/navigation and "Sign Up"/"Log In" links only; no lesson body, video, or challenge content. Lesson bodies are therefore not reachable by simple fetch, which is consistent with the link-only design.
- Practical consequence for the app: do not plan any runtime link-checker or metadata fetcher against `www.chess.com`. A deep link opened by the user in their own browser/app is the only dependable integration. Own-game import should go through `api.chess.com` or a manually downloaded PGN.

### Reading for this project (my interpretation, not legal advice)

- Linking is expressly contemplated by §5, subject to the no-false-affiliation and lawful-site conditions. A link-only catalogue fits.
- Storing Chess.com lesson text, descriptions, diagrams or video in the app would hit §2(B) and §4(C). Store only URL, title and author/level as catalogue facts; write the app's own one-line labels.
- §4(D) item 1 names "educational tools" explicitly, and the catch-all requires written authorisation for "any other automated access". Automated harvesting of the lesson catalogue to build this app is therefore the risky act, not the linking. The fetches made for this audit were automated and low-volume; the safest path is for the link catalogue to be curated by hand in a browser, and for the app never to fetch `www.chess.com` at runtime. Combined with the Cloudflare challenge on scripted access, this should be recorded as a design constraint.
- §2(D)(d) restricts downloading game records "except as expressly permitted by us"; the PubAPI and the Download button documented in Chess.com's own help centre (Part 3) are those expressly provided routes.

## Part 3 — Own-game access

### 3.1 PubAPI documentation

- Documentation: https://www.chess.com/news/view/published-data-api — title "Published-Data API - Chess.com" — `fetched-ok`. Page header shows "Updated: Apr 22, 2026, 11:11 AM"; the document footer says "Last reviewed and updated: 2022-05-10". The two dates conflict; the body appears to be the 2022 text.

### 3.2 Endpoints (documented, and exercised live)

| Purpose | Endpoint | Status |
|---|---|---|
| List of monthly archives | `https://api.chess.com/pub/player/{username}/games/archives` | fetched-ok for `https://api.chess.com/pub/player/erik/games/archives` (HTTP 200, JSON, 233 archive URLs, oldest first) |
| One month, JSON | `https://api.chess.com/pub/player/{username}/games/{YYYY}/{MM}` | fetched-ok for `https://api.chess.com/pub/player/erik/games/2026/10` (HTTP 200, 16 games) |
| One month, PGN | `https://api.chess.com/pub/player/{username}/games/{YYYY}/{MM}/pgn` | fetched-ok for `https://api.chess.com/pub/player/erik/games/2026/10/pgn` (HTTP 200, 16 games) |
| Player stats | `https://api.chess.com/pub/player/{username}/stats` | unverified (documented on the fetched docs page with example `https://api.chess.com/pub/player/erik/stats`; not requested) |

`erik` is the example account used in Chess.com's own documentation. Per the docs, `YYYY` is the four-digit year of the game end and `MM` the two-digit month. The archives endpoint returns the archive URLs in ascending order.

Docs quotes for the PGN endpoint: "standard multi-game format PGN containing all games for a month." and "This download follows the PGN standard, and is not JSON-encoded."

### 3.3 Game record fields

Documented fields for a monthly-archive game: `white` and `black` (each `username`, `rating`, `result`, `@id`), `accuracies` (`white`, `black`; only if previously calculated), `url`, `fen`, `pgn`, `start_time` (Daily only), `end_time`, `time_control`, `rules`, `eco`, `tournament`, `match`. The docs say `rating` is the rating after the game. The docs do **not** list `time_class` for this endpoint and do **not** mention clock annotations.

Observed on 2026-11-10 in the live response (16 games):

- Top-level keys: `url`, `pgn`, `time_control`, `end_time`, `rated`, `tcn`, `uuid`, `initial_setup`, `fen`, `time_class`, `rules`, `white`, `black` (16 of 16); `start_time` (15), `eco` (15), `accuracies` (14), `match` (5).
- Player object keys: `rating`, `result`, `@id`, `username`, `uuid`.
- `time_class` IS present (values seen: `daily`, `bullet`). `time_control` values seen: `60+1`, `1/259200`, `1/604800`, `1/86400`. `rules` values seen: `chess`, `chess960`. `rated` is a boolean.
- `eco` is a URL to a Chess.com opening page, not an ECO code.
- PGN tags seen: Event, Site, Date, Round, White, Black, Result, CurrentPosition, Timezone, ECO, ECOUrl, UTCDate, UTCTime, WhiteElo, BlackElo, TimeControl, Termination, StartTime, EndDate, EndTime, Link.
- **Clock comments are present**: every move carries `{[%clk h:mm:ss(.d)]}`. All 16 JSON `pgn` strings contained `%clk`; the PGN-endpoint file contained 1,086 `%clk` annotations across 16 games.
- The PGN has no time-class tag; from the PGN route, time class must be derived from `TimeControl`. The JSON route gives it directly.

Caution: `time_class`, `rated`, `uuid`, `tcn`, `initial_setup` and the `%clk` annotations are present in practice but absent from the documented monthly-archive schema. Treat them as undocumented and write the importer to tolerate their absence. `accuracies` is absent when no game review was run.

### 3.4 Rate limits, caching, headers

Documented:
- "Your serial access rate is unlimited."
- "If you always wait to receive the response to your previous request before making your next request, then you should never encounter rate limiting."
- For parallel requests: "then some requests may be blocked depending on how much work it takes to fulfill your previous request." and be prepared for a "429 Too Many Requests" response "for any non-serial request that you make."
- The docs also say an application may be blocked entirely if abnormal or suspicious activity is detected (paraphrase).
- User-Agent: "If you supply a recognizable user-agent that contains contact information" then, if the application must be blocked, "we will attempt to contact you to correct the problem." This is a request, not a stated requirement. No example header is given.
- Caching: "Each response has `ETag` and `Last-Modified` headers"; clients may send `If-None-Match` / `If-Modified-Since` and receive "304 Not Modified". Gzip is supported via `Accept-Encoding: gzip`.
- Refresh interval is stated inconsistently: "This endpoints refresh at most once every 12 hours" in one place and "The endpoints refresh at most once every 24 hours, if not noted otherwise." in another.

Observed:
- All three responses carried `ETag` and `Last-Modified`.
- `Cache-Control: public, max-age=60` on the archives list; `public, max-age=5` on the current-era month JSON and PGN.
- PGN response `Content-Type: application/vnd.chess-pgn; charset=utf-8` (docs say `application/x-chess-pgn`) and `Content-Disposition: attachment; filename="ChessCom_erik_202610.pgn"`.
- No `X-RateLimit-*` or `Retry-After` headers were present on the 200 responses.
- Requests were sent with a generic User-Agent containing no personal details and succeeded. Whether a request with no/default User-Agent is rejected was not tested.

Importer guidance that follows: one request at a time, send a descriptive User-Agent (the user can decide whether to add contact details), store `ETag` per month and use conditional requests, re-fetch only the current month routinely, handle 429 with backoff.

### 3.5 Stated terms for the data

- Scope: "Public Data" is "information available to people who are not logged in, such as player data, game data, and club/tournament information." Private data such as game chat and conditional moves is excluded (paraphrase).
- "This is read-only data. You cannot send game-moves or other commands to Chess.com from this system."
- "Our APIs and documentation are public, and we want the chess ecosystem to thrive."
- "we do require that you respect our IP: board color palettes, piece designs, sound effects, move classification glyphs"
- "If you're building something and aren't sure if it might cross a line, please write to us at" legal@chess.com.
- Daily-puzzle republication requires credit "by means of a clearly visibile text link" [sic].
- The page contains no explicit licence or commercial-use clause for game data; it links to the User Agreement. So the User Agreement (Part 2) governs, including the §2(D) non-commercial limits on game records.
- Design implication: the app must not copy Chess.com board themes, piece sets, sounds, or move-classification glyphs.

### 3.6 Manual route (website UI)

Sources:
- https://support.chess.com/en/articles/8705305-how-do-i-get-a-pgn-of-my-game — "How do I get a PGN of my game? | Chess.com Help Center", dated February 10, 2026 — fetched-ok
- https://support.chess.com/en/articles/8598090-how-do-i-view-my-own-games — "How do I view my own games? | Chess.com Help Center", dated August 10, 2026 — fetched-ok

Multiple games (web):
1. Hover over **Play** in the left menu and choose **Game History**. The archive is also at https://www.chess.com/games/archive (unverified: named in the fetched support article; requires login, not fetched).
2. Filter with the tabs (All, Favorites, Live, Daily, Bot, Coach) and the dropdown filters.
3. Tick the box beside each game, or tick the select-all box (described as the top box next to the Date dropdown in one article and as the 'Select All' box "on the far right below the game type tabs" in the other).
4. Click the **Download** icon.
5. Tick or untick the **clock icon** next to the download button to include or exclude timestamps.

Limits stated: select-all covers the games shown on screen, and search results show up to 100 pages (narrow with filters to reach older games). The number of games per page is not stated officially.

Single game (web): open the game, click the **Share** icon at the bottom of the Analysis tab, choose the **PGN** tab, click **Download**; tick the clock box for timestamps. After running analysis, the PGN options include Highlights, Comments, PGN Timestamp and Computer Analysis (annotations or computer analysis, not both).

Mobile: Android — **More** > **Export PGN**. iOS — magnifying glass (Game Analysis) > **Options** > **Share**. No bulk download in the apps is described.

The same support article also directs users to the PubAPI monthly PGN URL as a one-click browser download, using the pattern `https://api.chess.com/pub/player/{username}/games/{year}/{month}/pgn`. That is useful: Chess.com itself presents the API URL as an end-user route, and it works by pasting into a browser with no login.
