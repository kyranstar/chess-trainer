# Lichess source-feasibility audit

Audit date: 2026-11-10. Unauthenticated, no login. Roughly 20 requests to lichess.org hosts and 25 to GitHub raw/API, npm, readthedocs.

Verification labels used for every URL:

- `fetched-ok` = I fetched it and saw the expected content.
- `search-result-only` = appeared in a web search result; I did not read the page.
- `unverified` = constructed, guessed, or seen only as a link inside another page.

Important access note: after about 10 requests, lichess.org started answering HTML page requests with a Cloudflare challenge (HTTP 403, "Just a moment... Enable JavaScript and cookies to continue"). I did not try to get around it. That is why a few lichess.org pages below are `unverified` or `search-result-only`. The `/api/study/*.pgn` endpoints and the tablebase/explorer hosts kept answering normally.

---

## Headline findings

1. **Opening explorer now requires an OAuth token.** Both `explorer.lichess.org` and `explorer.lichess.ovh` returned `HTTP 401 Authorization Required` to an anonymous request today. The API spec was changed on 2026-03-03 to `security: - OAuth2: []`. For this app (no mandatory account, offline-first), computing move frequencies offline from the CC0 monthly dumps is the better fit.
2. **Practice/Learn lesson text is not clearly licensed for bundling.** The short titles and one-line descriptions are in the lila repo (AGPL-3.0-or-later). The actual chapter content lives in Lichess studies with no public licence statement found: **unclear, so link only**.
3. **Puzzle database and the English theme descriptions are both CC0** and may be bundled.
4. **chessground and chessops are GPL-3.0-or-later.** A publicly hosted app that bundles them must offer its source under GPL-compatible terms. The unscoped npm package `chessground` is deprecated; the live one is `@lichess-org/chessground`.

### 2.3 Documented semantics (exact quotes)

- Moves: "Moves are in UCI format. Use a chess library to convert them to SAN, for display."
- **First-move rule:** "FEN is the position before the opponent makes their move." / "The position to present to the player is after applying the first move to that FEN." / "The second move is the beginning of the solution."
  - So: the first move in `Moves` is played by the **opponent**; the **solver is the side NOT to move in the FEN**. Solver moves are at indices 1, 3, 5...; opponent replies at 0, 2, 4...
- Only-moves: "All player moves of the solution are \"only moves\". I.e. playing any other move would considerably worsen the player position."
- Mate exception: "An exception is made for mates in one: there can be several. Any move that checkmates should win the puzzle."
- Popularity: "Popularity is a number between 100 (best) and -100 (worst)." "It is calculated as 100 * (upvotes - downvotes)/(upvotes + downvotes), although votes are weighted by various factors such as whether the puzzle was solved successfully or the solver's puzzle rating in comparison to the puzzle's."
- Rating: "To determine the rating, each attempt to solve is considered as a Glicko2 rated game between the player and the puzzle."
- Themes: "You can find a list of themes, their names and descriptions, in this file." (links to puzzleTheme.xml, see 2.5). In the CSV they are space-separated keys.
- OpeningTags: "The OpeningTags field is only set for puzzles starting before move 20." Possible values: https://github.com/lichess-org/chess-openings - `unverified` as a page; its README at https://raw.githubusercontent.com/lichess-org/chess-openings/master/README.md is `fetched-ok`.
- DailyDate: "The DailyDate field is a Unix timestamp in milliseconds. If present, it indicates the date when the puzzle was featured as a daily puzzle".
- Provenance: "We went through 600,000,000 analysed games from the Lichess database, and re-analyzed interesting positions with Stockfish NNUE at 40 meganodes." Tags were "automatically tagged" and "player votes refine the tags and define popularity."

Not explicitly documented on the page (names only): `PuzzleId`, `RatingDeviation`, `NbPlays`, `GameUrl`.

Two things to watch in the app:

1. In all four documented sample rows, `GameUrl` carries `/black` exactly when the FEN is Black to move (that is, when the **opponent** is Black and the solver is White). Do not derive the solver's colour from the `/black` suffix; derive it from the FEN as above. (Observation from 4 samples, not a documented rule.)
2. The documented "any checkmating move wins" exception is stated for mates in one. To honour the project rule of never marking a sound move wrong, accept any move that delivers checkmate, and treat a non-solution move as "not the puzzle line" rather than "objectively bad" unless an engine confirms it.

## Part 3 - Opening move statistics

### 3a. Opening explorer API

Sources:

- API reference page https://lichess.org/api - `fetched-ok`, but it is a JavaScript shell; the content below is from the spec source it renders.
- Spec root: https://raw.githubusercontent.com/lichess-org/api/master/doc/specs/lichess-api.yaml - `fetched-ok` (version 2.0.178).
- `/lichess` endpoint spec: https://raw.githubusercontent.com/lichess-org/api/master/doc/specs/tags/openingexplorer/lichess.yaml - `fetched-ok`.
- Server README: https://raw.githubusercontent.com/lichess-org/lila-openingexplorer/master/README.md - `fetched-ok`.

**Hostname.** The spec now says: "The hostname for these endpoints is `explorer.lichess.org` and not `lichess.org`." It was `explorer.lichess.ovh` until spec commit https://github.com/lichess-org/api/commit/ac27c30086a66ba6bd00b399341e5e6ca0906eec (2026-03-03, "update explorer/tablebase doc"; read via the GitHub API, `fetched-ok`). The server README still shows `explorer.lichess.ovh` in an example.

**Endpoints** (paths in the spec): `/masters`, `/lichess`, `/player`, `/masters/pgn/{gameId}`.

**`GET https://explorer.lichess.org/lichess` parameters** ("Aggregated rated games from all Lichess players."):

| Param | Documented meaning |
|---|---|
| `variant` | default `standard` |
| `fen` | "X-FEN or EPD of the root position" |
| `play` | "Comma separated sequence of legal moves in UCI notation. Play additional moves starting from `fen`." |
| `speeds` | "Comma separated list of game speeds to filter by" (enum is in a schema file I did not fetch; the `/player` README lists `ultraBullet`, `bullet`, `blitz`, `rapid`, `classical`, `correspondence`) |
| `ratings` | "Comma separated list of ratings groups to filter by. Each group ranges from its value to the next higher group in the enum (`0` from 0 to 999, `1000` from 1000 to 1199, ..., `2500` from 2500 to any rating above)." Enum: 0, 1000, 1200, 1400, 1600, 1800, 2000, 2200, 2500 |
| `since` / `until` | month bounds, defaults `1952-01` / `3000-12` |
| `moves` | "Number of most common moves to display", default 12 |
| `topGames` | default 4, maximum 4 |
| `recentGames` | default 4 |
| `history` | boolean, default false |

Spec example: `curl https://explorer.lichess.org/lichess?variant=standard&speeds=blitz,rapid,classical&ratings=2200,2500&fen=rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR%20w%20KQkq%20-%200%201`

**Current authentication requirement: YES, a token is required.**

- Spec: every opening explorer operation now has `security: - OAuth2: []` (was `security: []` before the 2026-03-03 commit). The empty scope list means no particular scope is named.
- Live test today, anonymous, same query on both hosts:
  - https://explorer.lichess.org/lichess?... - `fetched-ok` as a probe: **HTTP 401**, body "401 Authorization Required" (nginx).
  - https://explorer.lichess.ovh/lichess?... - `fetched-ok` as a probe: **HTTP 401**, same body.
- Announcement: https://lichess.org/@/thibault/blog/the-opening-explorer-now-requires-authentication/FSWh9Zg3 - `search-result-only` (direct fetch got the Cloudflare 403; the URL is also cited in the spec commit message). The search summary paraphrased it as: anonymous requests are no longer allowed, the explorer stays free for anyone with a Lichess account, and API users must add an OAuth token to each request. I could not read the post, so treat that wording as unconfirmed.
- Token creation page per spec: https://lichess.org/account/oauth/token - `unverified` (requires login; not visited). Usage form per spec: `-H "Authorization: Bearer {token}"`.
- I did not test an authenticated call (no login, per instructions), so the response shape and scope behaviour are unverified.

**Rate limits.** No explorer-specific numeric limit is documented in the spec or README. The general rule applies (see Part 4a): "Only make one request at a time." and on 429 "waiting one minute before retrying will be sufficient, but some limits may require longer." The README states an operational figure only: "As of February 2023, Lichess handles around 12k requests/minute".

**Terms about caching or storing aggregated results locally.** None found in the spec, the explorer README, or the Terms of Service. Relevant adjacent facts: the underlying game data is CC0 (Part 3b); the ToS allows using services "in your own applications"; Lichess "reserve[s] the right to ... revoke access temporarily or permanently as we see fit". So: not prohibited by anything I found, not explicitly granted either.

**Browser/PWA implication.** The 401 response includes `access-control-allow-origin: *` and `access-control-allow-headers: ...,Authorization`, so a browser call with a bearer token is technically possible. But the spec's token guidance says: "Do not hardcode tokens in your application's code" and "Be especially careful that they are not included in frontend bundles or apps that are shipped to users." For a statically hosted PWA, a token must never be in the bundle. Options are a user-pasted personal token stored locally (adds an account dependency), or a Mac-side build script that queries once and ships a static frequency table, or the fully offline route in 3b.

### 3b. Offline alternative: monthly standard rated dumps

Source: https://database.lichess.org/ (`#standard_games`) - `fetched-ok`.

- **Licence:** CC0, same statement as 2.4.
- **Scale:** "8,315,708,510 standard rated games", "Total: 166 files 2.63 TB". "Each file contains the games for one month only; they are not cumulative."
- **Typical recent monthly size (compressed .pgn.zst):** 2026-10: 31 GB, 95,395,628 games. 2026-09: 29.2 GB, 89,616,462. 2026-08: 30.1 GB. 2026-02: 27.8 GB, 84,600,043. Range over the last 18 months is about 28-31 GB and 85-95 million games. "Expect uncompressed files to be about 7.1 times larger." (so roughly 200-220 GB uncompressed per month). Earliest file 2013-01 is 17.8 MB.
- **File URL pattern** (relative link on the page): https://database.lichess.org/standard/lichess_db_standard_rated_2026-10.pgn.zst - `unverified` (link seen on fetched page, not requested). Also listed: `standard/list.txt` and `standard/sha256sums.txt` (`unverified`), and `.torrent` files.
- **PGN headers in the documented sample game:** `Event`, `Site`, `Date`, `Round`, `White`, `Black`, `Result`, `UTCDate`, `UTCTime`, `WhiteElo`, `BlackElo`, `WhiteRatingDiff`, `BlackRatingDiff`, `WhiteTitle` (when titled), `ECO`, `Opening`, `TimeControl`, `Termination`.
  - Sample values: `[Event "Rated Bullet tournament https://lichess.org/tournament/yc1WW2Ox"]`, `[WhiteElo "2100"]`, `[ECO "B30"]`, `[Opening "Sicilian Defense: Old Sicilian"]`, `[TimeControl "300+0"]`.
  - "The WhiteElo and BlackElo tags contain Glicko2 ratings."
  - Bots: "marked with [WhiteTitle \"BOT\"] or [BlackTitle \"BOT\"]".
  - "About 6% of the games include Stockfish analysis evaluations"; clock comments `%clk` since April 2017.
- **Streaming on a Mac:** "ZStandard archives are partially decompressable, so you can start downloading and then cancel at any point. You will be able to decompress the partial download if you only want a smaller set of game data." and "`$ zstdcat lichess_db.pgn.zst | python script.py`". So a script can stream without storing 200 GB, and can stop after a sample.
- **Known data issues** are listed on the page (for example bad evals in 2016/2020, a 2021 outage affecting results). None affects opening move counts materially for recent months.

Practical notes for the counting script (my assessment, not from the page):

- Full legal-move replay of 90 million games with python-chess (GPL-3.0-or-later) is slow. For a small fixed set of target positions, filter on headers first (`TimeControl`, both Elo values, skip `BOT`), then replay only the first N plies, or match SAN move-prefixes for the target lines and replay only the survivors to catch transpositions.
- Derive the speed band from `TimeControl` (base + 40 x increment is the Lichess convention; that formula is from memory and unverified here) or from the word in `Event`.
- A partial download gives an unknown slice of the month. Whether games in a monthly file are in chronological order is unverified.
- Record with each derived frequency: month(s) used, rating band definition, speed filter, and game count per position, to satisfy the project rule about showing sample size and time window.

### 4b. Study PGN export

Spec: https://raw.githubusercontent.com/lichess-org/api/master/doc/specs/tags/studies/api-study-studyId.pgn.yaml - `fetched-ok`.

- `GET https://lichess.org/api/study/{studyId}.pgn` - all chapters. "If authenticated, then all public, unlisted, and private study chapters are read. If not, only public (non-unlisted) study chapters are read." Confirmed working without a token on four public studies today.
- Query params: `clocks` (default true), `comments` (default true), `variations` (default true), `orientation` (default false).
- `HEAD` on the same URL returns headers including `Last-Modified` (useful for cheap change detection).
- Other paths listed in the spec root (not individually read): `/api/study/{studyId}/{chapterId}.pgn`, `/api/study/by/{username}/export.pgn`, `/api/study/by/{username}`, `/api/study/{studyId}/import-pgn`. Private studies need a `study:read` token.

**Licence of user-authored study annotations.** No public licence. Terms of Service: "You retain your rights in any content you submit to or through our website or services." The only licence granted is to Lichess ("you grant us a worldwide, non-exclusive, royalty-free license (with the right to sub-license that content)"). The ToS also lists as abuse "the sharing or distribution of chess literature, puzzle sets, annotations, or any other material or intellectual property you do not have the right to share or distribute."

Implication: third-party studies are all-rights-reserved by their authors unless the author states otherwise. **Link, or get the author's explicit permission before bundling.** The user's own studies are his to export and bundle. Bare move sequences and positions are generally treated as facts, but prose annotations are not (general legal background, not something stated on Lichess).

### 4c. Tablebase

- Spec: https://raw.githubusercontent.com/lichess-org/api/master/doc/specs/tags/tablebase/standard.yaml - `fetched-ok`. README: https://raw.githubusercontent.com/lichess-org/lila-tablebase/master/README.md - `fetched-ok`.
- Endpoint: `GET https://tablebase.lichess.org/standard?fen=<X-FEN, underscores allowed>`; optional `dtc` = `never` | `auxiliary` | `always`. Also `GET /standard/mainline?fen=` (README), plus `/atomic`, `/antichess`. Spec: "The hostname for these endpoints is `tablebase.lichess.org`".
- Auth: `security: []` - none. Live probes today, anonymous:
  - https://tablebase.lichess.org/standard?fen=4k3/6KP/8/8/8/8/7p/8_w_-_-_0_1 - `fetched-ok` (HTTP 200 JSON, `category: "win"`, `dtz: 1`, `dtm: 17`, per-move list).
  - https://tablebase.lichess.ovh/standard?fen=... (same) - `fetched-ok` (HTTP 200, identical). The old hostname still works.
- Response headers: `access-control-allow-origin: *`, `cache-control: max-age=1209600` and `public` (14 days), so results are explicitly cacheable.

Mainline: "Error 404 if not a tablebase position or required tables not present."
- Limits: no tablebase-specific numeric rate limit documented; the general "one request at a time" / 429 rule applies. Coverage: python-chess docs say Syzygy covers "all endgame positions with up to 7 pieces. Positions with castling rights are not included."

- **Pin the scoped name** `@lichess-org/chessground`; the unscoped `chessground` package is frozen at 9.2.1 and marked unsupported.
- chessground README (https://raw.githubusercontent.com/lichess-org/chessground/master/README.md - `fetched-ok`), exact: "Chessground is distributed under the **GPL-3.0 license** (or any later version, at your option). When you use Chessground for your website, your combined work may be distributed only under the GPL. **You must release your source code** to the users of your website."

**Implication for an app bundled with them and served from public static hosting** (my reading, not legal advice):

- Serving the bundled JavaScript to browsers is distribution of a combined work. The whole client app must then be licensed GPL-3.0-or-later (or compatible), and the complete corresponding source (unminified source plus build scripts) must be offered to anyone who can load the app. A public repository linked from the app, with licence notices preserved, is the usual way to comply.
- If the app is only ever used privately by one person and not made available to others, no distribution occurs and no source obligation is triggered. A public URL on free static hosting does make it available to others, even if unlisted. Access-restricted hosting, or simply publishing the source, removes the question.
- GPL-3.0 code cannot be combined with licence-incompatible proprietary content or code in the same distributed work. CC0 data (puzzles, theme descriptions, opening names, derived move frequencies) is fine. AGPL-3.0 material (for example `learn.xml` text) can be combined with GPL-3.0 code under GPLv3 section 13, with the AGPL terms continuing to apply to that part.
- Linked third-party course content (Chess.com, Chessreps, Lichess studies) is unaffected, since links are not part of the distributed work.
- If GPL is unacceptable, the alternative is a differently licensed board and rules library; that is outside this audit.
