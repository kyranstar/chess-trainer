# Accounts for invited friends — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Invited friends sign in once with Google, are greeted by name, link Chess.com and practise; progress is per account on the device with a copy in the account; the owner manages invites and alone has flags, which work on any screen.

**Architecture:** All account code sits behind `AccountService` (`src/account/`), with a Firebase implementation (Auth + Firestore Lite) used only when the build carries a Firebase config, and a fake (localStorage) that browser tests switch on. An `AccountGate` component in front of the existing `Shell` decides which screen shows and opens the account's own Dexie database; switching account reloads the page, so no module cache needs resetting. The account copy reuses `exportBackup`/`importBackup`, extended with per-setting change times.

**Tech Stack:** React 19, TypeScript, Dexie 4, Vite PWA; `firebase` (Auth, `firebase/firestore/lite`), pinned; `firebase-tools` + `@firebase/rules-unit-testing` (dev, pinned) for rules tests on the local emulator; Playwright; Vitest with fake-indexeddb.

**Spec:** `docs/superpowers/specs/2026-11-20-accounts-design.md`

## Global Constraints

- Local mode (no `VITE_FIREBASE_CONFIG` at build time) behaves exactly as today; every existing unit and browser test passes unchanged.
- No email address in the repository or bundle. The admin is whoever has `admins/{email}` in Firestore.
- Firebase config comes from `data/deploy.env` (`FIREBASE_CONFIG='{"apiKey":…}'`) through `scripts/deploy-pages.sh` as `VITE_FIREBASE_CONFIG`; `VITE_CHESSCOM_USERNAME` is no longer passed by the deploy script.
- `authDomain` is `kyranstar.github.io`.
- Sign in once: on iPhone/iPad and Mac Safari the install step comes before sign-in; elsewhere sign-in first. Auth persistence `indexedDBLocalPersistence`. Redirect sign-in on phones and in the installed app, popup on desktop with redirect if blocked.
- Copy chunks ≤ 900,000 characters; push at most every 120,000 ms (`REMOTE_MIN_INTERVAL_MS`), and when the page is hidden; online only.
- Screens say nothing about accounts, copies, databases or merging unless something needs attention (owner, 2026-11-20).
- The fake service is reachable only when the build has no Firebase config.
- Every dependency pinned to an exact version (`AGENTS.md`).
- Node 22.23.1: prefix shell commands with `source ~/.nvm/nvm.sh && nvm use >/dev/null &&`.

## Review Focus

1. Offline open of a signed-in, allowed account (subway): goes straight to Today, no network call blocks it. → Task 5, `e2e/accounts.spec.ts` "opens offline once allowed".
2. Two devices pushing in turn: the second must merge the first's copy before writing, losing nothing. → Task 2, `copy.test.ts` "a push behind the server merges first".
3. A friend opening on a device that holds the owner's old database: never adopted, owner's games never shown. → Task 3, `device.test.ts` "a member never adopts the old database".
4. A copy written by a newer app version (schema above ours): not merged, Account page says to update. → Task 2, `copy.test.ts` "a newer copy is held back".
5. A setting removed on one device (flag off, Chess.com unlinked, repertoire move declined) stays removed after a merge, while an old backup file without stamps still restores as before. → Task 1, `stamps.test.ts`.

### Task 2: The account copy (push and pull logic)

**Files:**
- Create: `src/account/copy.ts`, `src/account/copy.test.ts`
- Modify: `src/db/remote.ts` (export `gzipBase64`; reuse `decodeRemoteFile`)

**Interfaces:**
- Consumes: `exportBackup`, `serializeBackup`, `importBackup`, `parseBackup` (Task 1), `dataSignature`.
- Produces:
  - `interface CopyManifest { rev: number; chunks: number; bytes: number; sha256: string; exportTime: string; deviceId: string; appVersion: string; schemaVersion: number }`
  - `interface CopyStore { readManifest(): Promise<CopyManifest | null>; readChunks(m: CopyManifest): Promise<string[]>; write(expectedRev: number, m: CopyManifest, chunks: string[]): Promise<'ok' | 'conflict'> }` (`write` is a transaction: `'conflict'` when the stored rev ≠ `expectedRev`)
  - `CHUNK_CHARS = 900_000`
  - `pullCopy(db: TrainerDB, store: CopyStore): Promise<{ merged: boolean; heldBack?: 'newer-app' }>`: reads the manifest; if `rev` > local meta `copy.rev`, reads chunks, checks sha256, ungzips, `importBackup`, sets `copy.rev`. A manifest with `schemaVersion > SCHEMA_VERSION` returns `heldBack: 'newer-app'` without reading chunks.
  - `pushCopy(db: TrainerDB, store: CopyStore, now: number): Promise<{ ok: true; at: number } | { ok: false; reason: 'offline' | 'error' | 'newer-app'; detail?: string }>`: skips when `dataSignature` equals meta `copy.signature`; else export → gzip → base64 → chunks → `write(localRev, …rev+1…)`; on `'conflict'` pulls, then retries once more; stores `copy.rev`, `copy.signature`, `copy.at`.
  - `memoryCopyStore(): CopyStore & { manifest: CopyManifest | null }` (for tests and the fake service)
  - Meta keys `copy.rev`, `copy.signature`, `copy.at`, `copy.error` are device bookkeeping (not portable).

- [ ] **Step 1: Write failing tests** in `copy.test.ts`:
  - `"round trip through chunks"`: with `CHUNK_CHARS` forced small (export a setter `__setChunkChars` for tests), push from A, pull into empty B → B has A's attempts; `manifest.chunks > 1`.
  - `"a push behind the server merges first"`: A pushes (rev 1); B (rev 0) answers 3 attempts, pushes → B pulls A's then writes rev 2 containing both; A pulls → has B's attempts.
  - `"nothing to send is not sent"`: second push with no change leaves `rev` unchanged.
  - `"a damaged chunk is refused"`: alter a chunk → `pullCopy` throws, local data unchanged.
  - `"a newer copy is held back"`: manifest `schemaVersion: SCHEMA_VERSION + 1` → `{ merged: false, heldBack: 'newer-app' }` and `pushCopy` returns `reason: 'newer-app'` without writing.
- [ ] **Step 2: Run** `npx vitest run src/account/copy.test.ts` → FAIL.
- [ ] **Step 3: Implement** `copy.ts`.
- [ ] **Step 4: Run** → PASS.
